Daily Cheer Autopilot

A local bot that finds colleagues on Aster's Daily Cheer page and sends them a heart, so the whole company doesn't have to be rediscovered by hand every day.

auto-discovers colleagues · once-a-day heart limit

System architecture

Everything runs on one machine — yours. The bot never logs in on its own — it attaches to a Chrome tab you've already signed into, and never opens a new one.

What happens per search prefix

The bot doesn't know people's names up front — it discovers three-letter strings that return results on Aster's own search box, once, in a full sweep. Every daily run just replays that list, skipping what's already done.

How it's used

01 — once

Discover

full_sweep.py tries every non-repeating three-letter string against Aster's search box and records the ones that return people. Read-only — no hearts sent.

02 — daily

Run

Either python3 daily_cheer_bot.py from a terminal, or the "Heart Everyone" button on the dashboard — same engine either way.

03 — live

Watch

A progress bar and streaming log show each prefix as it's checked; Pause stops cleanly between prefixes, never mid-click.

04 — always

Count, never names

Every number on the dashboard and in every log line is a count. No name, no email, no searchable list -- anywhere.

Tech stack

Automation Playwright (Python) attaches to an existing browser instead of launching one
Transport Chrome DevTools Protocol remote-debugging-port, no browser extension needed
Browser real Google Chrome keeps the actual MetaMask session, not a throwaway profile
Dashboard backend Flask localhost-only, runs the bulk job in a background thread
Dashboard frontend vanilla HTML / CSS / JS no framework; polls a status endpoint every 800ms
State flat JSON files no database — a handful of local files are the entire memory

Safety boundaries

Rules the bot never breaks, on purpose.

Runs only on your machine, with your wallet. There's no shared server or shared account — everyone who wants this clones the repo and runs their own copy.
Never opens a new tab. A fresh tab re-triggers a MetaMask sign-in prompt the bot can't and won't approve — it always attaches to a tab you already opened.
Never touches the wallet. Connecting, signing, approving — all manual, every time, no exceptions.
Checks before it clicks. A disabled Heart button is read as "already hearted" and skipped — it never fires blind.
Dashboard is localhost-only. Bound to 127.0.0.1; nothing on the network can reach it.
Stores counts, never names. Nothing written to disk, printed to a console, or shown on the dashboard ever contains a name or email -- only how many people a search term matched and how many have been hearted.
